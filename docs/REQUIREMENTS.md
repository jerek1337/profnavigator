## Нефункциональные

### Отказоустойчивость

- Исключение при обработке сообщения не роняет бота: событие пишется в аналитику, пользователь получает кнопку «Продолжить».
- Упавший адаптер, веб-сервер или планировщик перезапускается супервизором в `main.py`.
- ИИ-провайдеры перебираются по цепочке, у каждого таймаут и повтор; сбоящий отключается на время (circuit breaker); при исчерпании общего бюджета выдаётся шаблон.
- Ответ на каждый вопрос, включая последний, сохраняется до обращения к ИИ и до отправки сообщений.
- Отправка сообщения не повторяется при сетевой ошибке — повторяются только идемпотентные запросы. Повторно доставленные события отсеиваются по идентификатору.
- Сообщения одного пользователя обрабатываются последовательно (блокировка по uid).

### Производительность

- Ответ без ИИ мгновенный: логика подбора локальная, SQLite в режиме WAL.
- `AI_TIMEOUT` — таймаут на провайдера (20 с), `AI_TOTAL_TIMEOUT` — общий бюджет (30 с), далее шаблон.
- На время генерации показывается индикатор ожидания.
- Long polling: до 100 событий за опрос, обработка параллельная.

### Безопасность и приватность

- Хранятся ответы теста и технические события. Имя в аналитику не попадает, тексты свободных вопросов не сохраняются — только длина.
- `/forget` удаляет профиль и все события пользователя.
- Ссылки между мессенджером и вебом подписаны `SECRET_KEY`; если он пуст, ключ генерируется и хранится в базе.
- Дашборд закрыт `ADMIN_TOKEN`, страница помечена `noindex`.
- Входящее сообщение — до 500 символов, свободный ответ — до 100. На вопросы к ИИ действует `QA_DAILY_LIMIT`.
- Секреты только в переменных окружения, `.env` исключён из репозитория и из образа.
- Контейнер работает от непривилегированного пользователя.

### Сопровождаемость

- Ядро общается с адаптерами объектами `Incoming` и `Reply` и не знает о платформах.
- Новая платформа — файл в `adapters/` с методами `run()` и `send_to_user()`.
- Новая команда или кнопка — `engine.register_command()` / `register_action()`.
- Вопросы, профессии и тексты в `core/content.py`, правятся без знания Python.
- Новый ИИ-провайдер — класс с `complete()` и запись в `PROVIDER_FACTORIES`.
- Хранилище изолировано классом `Storage`: SQLite заменяется на PostgreSQL реализацией тех же методов.

### Тестируемость

40 автотестов, одна команда, без сети и внешних сервисов. Покрыты: полный сценарий, свободный ввод и валидация, подбор профессий, напоминания, аналитика, оба мессенджер-адаптера, политика повторов, отказоустойчивость ИИ, веб-эндпоинты.

## Ограничения

- Закрытых библиотек, частных API и чужого кода без открытой лицензии не используется. Вся логика написана в рамках проекта, единственная внешняя зависимость `qrcode` распространяется под BSD и является необязательной. Проект под MIT.
- Внешние API только публичные: MAX Bot API, Telegram Bot API, YandexGPT, GigaChat, OpenAI-совместимые.
- Система пользователя не изменяется. Корневые сертификаты, включая НУЦ Минцифры для GigaChat, подключаются файлом через `GIGACHAT_CA_BUNDLE` в рамках процесса, а не установкой в системное хранилище.
- Данные несовершеннолетних минимизированы и удаляемы, за пределы сервиса не передаются.

## Известные ограничения версии

- Адрес API MAX (`MAX_API_URL`) стоит сверить с dev.max.ru перед боевым запуском: в документации встречается и `platform-api2.max.ru`.
- Снятие кнопок у предыдущего вопроса сокращает, но не исключает гонку при частых нажатиях: события, уже стоящие в очереди мессенджера, всё равно придут.
- Кэш обработанных событий живёт в памяти процесса и пуст после перезапуска.
- Long polling подходит для пилота в школе; на большей нагрузке MAX рекомендует webhook.
